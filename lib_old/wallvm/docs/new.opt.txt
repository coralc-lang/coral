--Static Spatial Layout Sorting of Stack Variables (Anti-Clustering) [DONE - stack_layout.crl]

    What it does: Most compilers allocate local stack variables in the order they are declared or encountered. This optimization reorganizes and re-sorts local variables on the stack frame entirely based on access frequency and size class, grouping hot variables together to fit within a single 64-byte cache line, while pushing cold variables (like large error buffers or infrequent flags) to separate lines.

    Why it's non-mainstream: Compilers usually leave stack layout to simple linear allocation or basic alignment rules. Doing a static data-flow analysis of access frequency to layout local stack frames directly improves L1 data cache hit rates across generic architectures without requiring profiling passes.

--Return Value Optimization (RVO) Propagation [DONE - sroa.crl]

    Replaces alloca→store→load chains with direct value forwarding when safe.

--Control-Flow Tail Duplication [DONE - tail_dup.crl]

    Duplicating the tail of a basic block into its incoming jump targets to eliminate unconditional branches and expose further constant folding or selection patterns across basic block boundaries.

--Instruction Density / Code Size Packing (Macro-Fusion Prep) [DONE - macro_fusion.crl]

    Rearranging independent micro-operations into tight sequence pairs that are known to pair well in decoders across standard architectures (like matching a compare/test instruction directly adjacent to a conditional branch) to make hardware macro-fusion easier for generic x86 and ARM decoders.

--Idempotent Op Removal / Redundant Write Suppression [DONE - idempotent.crl]

    Detecting consecutive, identical store operations to the same memory location or register where no intervening read or side effect occurs, stripping out the redundant write entirely.

--Redundant Branch Inversion Flattening [DONE - branch_inversion.crl]

    What it does: When code contains sequential conditional checks that evaluate overlapping or inverse predicates (e.g., checking if (x > 5) in one block and later if (x <= 5) without modifying x), this optimization tracks the path constraints through the CFG and replaces the second branch with an unconditional jump or direct register state propagation.

    Why it's non-mainstream: While basic branch folding handles immediate if/else blocks, deep path-sensitive inversion tracking across complex, separated basic blocks is usually bypassed by mainstream compilers unless heavy global value range propagation (VRP) is running, making it a lighter-weight alternative to capture logic redundancies.

--Jump-to-Jump (Branch Chain) Flattening [DONE - jump_thread.crl]

    Scans basic block terminators for unconditional branches that point directly to another unconditional branch (e.g., block A jumps to block B, and block B's only content is an unconditional jump to block C). The pass rewrites block A's target directly to C.

--Commutative Operand Canonicalization Pass [DONE - comm_canon.crl]

    For commutative operations (like addition, multiplication, bitwise AND/OR/XOR), this pass enforces a strict, deterministic ordering on the operands (e.g., sorting them by value ID, register name, or constant status so that smaller IDs or constants always appear on the left).

--Involution Chain Collapse (Self-Inverse Elimination) [DONE - involution.crl]

    Identifies adjacent or chained pairs of operations that are exact inverses of each other (involutions) and strips them both out entirely.

--Redundant Type Cast and Extension Elimination [DONE - cast_elim.crl]

    Analyzes value ranges or source types to eliminate nested, redundant casting operations. Handles 10 patterns including trunc(zext), zext(sext), fpext(fptrunc), bitcast(bitcast), etc.

--Lexicographical Canonicalization of Commutative Trees [DONE - lex_canon.crl]

    Flattens deeply nested, associative, and commutative expression chains (like additions or bitwise operations, e.g., (c + (a + b))) and deterministically sorts the operand nodes using a strict lexicographical ID or weight order.

--Global Redundant Type-Cast Striping [DONE - cast_elim.crl]

    Scans the IR for chains of conversion operations (such as i32 -> i64 -> i32 or truncation followed immediately by zero-extension) where the intermediate type conversion is proven redundant because the value's range never exceeded the narrower bounds.

--Static Branch-Condition Factoring (Guard Extraction) [DONE - branch_factoring.crl]

    Identifies adjacent or nested basic blocks that evaluate overlapping boolean sub-expressions (e.g., checking if (x > 5) in one branch and later if (x > 5 && y < 10)), and factors out the dominant invariant checks into a single leading block.
